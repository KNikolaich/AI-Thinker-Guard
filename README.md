# AI-Thinker Guard

Прошивка наблюдения для **AI-Thinker ESP32-CAM**: обнаружение движения, фотографии в Telegram, команды бота с кнопками, плановые снимки, присутствие капитана по Wi-Fi, тихие часы, страница настройки и OTA.

**Версия прошивки:** 1.8.0  
**Плата:** AI Thinker ESP32-CAM (OV2640)  
**Arduino-ESP32:** 2.0.17

## Возможности

- Сравнивает последовательные кадры (уменьшенный до 80×60 серый кадр из JPEG VGA); при движении отправляет `N` фотографий. Следующее событие по движению отправляется не раньше, чем через `TO` секунд.
- Раз в `X` минут отправляет плановую фотографию.
- Работает с несколькими чатами (до 5, ID через запятую): тревоги, плановые снимки и уведомления получают все; фото загружается один раз и пересылается остальным по `file_id`, трафик не растёт. Другие чаты игнорируются, но ID последнего незнакомого чата виден на странице «Состояние».
- Команды бота (отвечает только спросившему чату, в том числе в тихие часы):
  - `/getcapture` (или `GetCapture`) — `M` свежих фото;
  - `/status` — состояние камеры, капитана, тихих часов, Wi-Fi;
  - `/start`, `/help` — описание: как часто и что присылает, список команд.
  Под ответами — inline-кнопки «📷 Снимок», «ℹ️ Статус», «❓ Помощь». Команды также появляются в меню «/» бота.
- Опционально следит за телефоном капитана в домашней Wi-Fi сети: раз в 15 секунд отправляет ARP-запрос на его IP. Когда телефон появляется в сети, отправляет «Капитан на постике»; когда молчит дольше заданного времени (по умолчанию 10 минут) — «Сторож бдит». Пока капитан в сети, тревоги по движению подавляются.
- Поддерживает тихий интервал, в том числе через полночь, с часовым поясом в минутах от UTC.
- Хранит настройки во внутренней NVS через `Preferences`; SD-карта для работы не требуется.
- Если камера не подключена, Wi-Fi и страница настройки всё равно запускаются; камера-зависимые действия пропускаются.
- Если сохранённая сеть Wi-Fi недоступна 20 секунд (или Wi-Fi ещё не настроен), поднимает точку доступа `Guard-XXXXXX` с веб-страницей на порту 80 (адрес `192.168.4.1`, телефон обычно открывает её сам). Подключение к домашней сети при этом продолжает повторяться каждые 30 секунд; когда Wi-Fi стабилен 2 минуты и к точке никто не подключён, она выключается. Если Wi-Fi пропал во время работы, точка настройки поднимается через 30 секунд.
- Пароль резервной точки доступа не меняется: `Guard` + 5 цифр из MAC (например, `Guard95733`), печатается в Serial Monitor при каждой загрузке и виден в блоке «Состояние».
- Пароль веб-панели (логин `admin`) и OTA по умолчанию такой же; свой (8–63 символа) задаётся на странице или командой `setpassword`. Если пароль панели задан вручную, панель спрашивает логин и через точку доступа. OTA по умолчанию выключена.
- Меню вверху панели: «Обновить прошивку», «Сохранить конфиг» (файл JSON), «Загрузить конфиг» — удобно для переноса настроек между камерами.

## Отказоустойчивость

- Wi-Fi/точка доступа и страница настроек запускаются **первыми** и не зависят от камеры, Telegram и NVS. Ни одна ошибка модуля не останавливает прошивку и не уводит её в бесконечный цикл.
- Текущий этап запуска хранится в RTC-памяти. Если камера вызвала аварийный перезапуск (abort, watchdog, просадка питания), на следующей загрузке она пропускается, остальное работает. После трёх сбоев подряд в других местах включается **безопасный режим**: работают только Wi-Fi и страница настроек.
- Блокировки снимаются при отключении питания, при сохранении настроек или кнопкой «Повторить инициализацию всех модулей» на странице.
- Вверху страницы настроек — блок «Состояние»: Wi-Fi, точка доступа, камера, капитан, Telegram (последний ответ API), OTA, память, причина последнего перезапуска. Проблемы подсвечены красным.
- Камера при ошибке повторно инициализируется каждые 5 минут; при пропаже кадров во время работы — отключается и тоже переинициализируется.
- Сторожевой таймер основного цикла (90 с): зависание приводит к перезапуску, а не к «мёртвому» устройству.
- Повреждённый раздел NVS очищается и создаётся заново; если NVS недоступна совсем, устройство работает на настройках по умолчанию.
- Без интернета опрос Telegram замедляется до одного раза в минуту, чтобы страница настроек отвечала быстро.

## Ограничения, важные до установки

1. **Нельзя сохранить фото без SD-карты.** Во время тихих часов и сетевых сбоев прошивка накапливает в RAM только счётчики событий; после восстановления отправляет сводку и один новый, актуальный кадр. Исходные кадры и точная очередь снимков после перезапуска теряются.
2. **Присутствие капитана — это «телефон в Wi-Fi сети камеры», а не «рядом с камерой».** Зона — всё покрытие роутера. Телефон должен быть подключён к этому Wi-Fi (если на телефоне выключен Wi-Fi, капитан считается ушедшим). За телефоном нужно закрепить постоянный IP в роутере. Спящий телефон иногда отвечает с задержкой, поэтому уход фиксируется не сразу, а после заданного числа минут молчания.
3. Для расписания нужен доступ к NTP. Пока часы не синхронизированы, режим тишины временно не применяется.
4. Telegram Bot API использует TLS, но в этой версии `WiFiClientSecure::setInsecure()` отключает проверку сертификата. Это упрощает совместимость, но оставляет риск MITM в недоверенной сети. Используйте доверенную Wi-Fi сеть; для эксплуатации в недоверенной сети следует добавить проверку корневого сертификата.
5. На ESP32-CAM мало свободной памяти. N и M ограничены 1–5 снимками за запрос; большие серии, плохой Wi-Fi или крупные JPEG могут задерживать обработку остальных задач.
6. Пароль, токен и остальные настройки хранятся в NVS. В этой конфигурации NVS не защищена включённым шифрованием flash; HTTP-панель использует Basic Auth без TLS, поэтому открывайте её только в доверенной локальной сети.

## Arduino IDE

1. Установите пакет плат ESP32 и выберите именно **AI Thinker ESP32-CAM**. Для установки подходит пакет Espressif, в котором доступна версия **2.0.17**. В проекте нет зависимости от ESP8266 core.
2. Установите библиотеку **ArduinoJson 6.x** через Library Manager. Камера, `WebServer`, `Preferences`, `WiFiClientSecure` и `ArduinoOTA` поставляются с ESP32 core.
3. Откройте `AIThinkerGuard.ino` из папки проекта.
4. В меню платы включите **PSRAM**, установите **Flash Mode: DIO** и выберите раздел с OTA-поддержкой (например, **Minimal SPIFFS (1.9MB APP with OTA)**, если этот вариант доступен), а не профиль `No OTA`.
5. Для первой прошивки используйте USB–UART адаптер 3.3 V: подключите `U0R↔TX`, `U0T↔RX`, `GND↔GND`, подайте стабильное питание 5 V на `5V`; для режима загрузчика замкните `GPIO0` на `GND` только при сбросе, затем разомкните после старта загрузки. Не подавайте 5 V на UART-пины.
6. После прошивки откройте Serial Monitor на **115200** бод.

Если появляется `assert failed: do_core_init ... (flash_ret == ESP_OK)`, проверьте точную плату **AI Thinker ESP32-CAM** и соответствие параметра **Flash Size** реальной памяти модуля (обычно 4 MB). В Serial Monitor найдите строки `spi_flash` перед assert: сообщение о том, что найденный размер меньше размера в заголовке прошивки, указывает на несовпадение настроек. Если boot log уже показывает `mode:DIO`, режим DIO активен — повторно менять QIO на DIO не нужно.

Дополнительные URL плат Espressif, которые пользователь применяет:

```text
https://dl.espressif.com/dl/package_esp32_index.json
https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
```

## Первичная настройка

1. Если сеть Wi-Fi ещё не настроена, при старте появится AP с именем `Guard-XXXXXX`; пароль точки печатается в Serial Monitor при каждой загрузке (`Guard` + 5 цифр из MAC). Подключитесь к AP и откройте `http://192.168.4.1/`.
2. Если сохранённый Wi-Fi недоступен 20 секунд, устройство также поднимет AP (и продолжит попытки подключения в фоне). В обычном режиме страница настроек доступна по IP камеры в домашней сети.
3. Через точку доступа панель открывается без логина, пока пароль панели не задан вручную (телефон обычно сам показывает окно «Вход в сеть»). Из домашней сети войдите пользователем `admin` с паролем панели. Забытый пароль показывает команда `password` в Serial Monitor.
4. Заполните SSID/пароль Wi-Fi, токен Telegram-бота, ID чатов через запятую, N, M, X и TO; сохраните настройки. Пустые парольные поля Wi-Fi/Telegram оставляют прежнее значение. Пустое поле нового пароля устройства тоже означает «оставить прежний».
5. Напишите боту `/start` из чата, чей ID указан: придёт описание с кнопками. Нажмите «📷 Снимок» для проверки.
6. Для OTA установите флажок «Разрешить OTA». Отдельный пароль не нужен: используется пароль веб-панели. Пока флажок снят, OTA отключена. На следующей загрузке при подключённом Wi-Fi OTA будет доступна на порту 3232. Для перепрошивки выберите сетевой порт `ai-thinker-guard` в Arduino IDE. Текущая версия в прошивке — `1.8.0`.
7. Чтобы включить присутствие капитана, закрепите за его телефоном постоянный IP в роутере (Keenetic: «Список устройств» → телефон → «Постоянный IP-адрес») и впишите этот IP в панель. Оставьте поле пустым, чтобы отключить функцию. На странице «Состояние» видно, отвечает ли телефон и когда ответил последний раз.

Без токена бота или ID чатов Telegram отключён, но устройство и панель настройки продолжают работать. Пустой IP телефона отключает только присутствие капитана. Неудачная инициализация камеры не останавливает Wi-Fi и панель. При обновлении со старой версии старый веб-пароль переносится, старый отдельный пароль OTA удаляется, а OTA остаётся выключенной до явного включения.

Настройки сохраняются в NVS (не стираются при обычном перезапуске или OTA). Для повторного подключения к точке настройки достаточно, чтобы домашняя сеть была недоступна: через 20–30 секунд устройство создаст AP. Все настройки можно сохранить в файл кнопкой «Сохранить конфиг» и загрузить на эту или другую камеру.

## Если Telegram заблокирован: прокси на своём VPS

В настройках есть поле «Адрес API Telegram» (`host[:порт][/путь]`, пусто — `api.telegram.org`). Укажите там свой сервер, который пересылает запросы в `api.telegram.org`. Для провайдера это обычный HTTPS к вашему серверу. Пример nginx (Ubuntu/Debian, самоподписанный сертификат — прошивка сертификат не проверяет):

```nginx
server {
    listen 8443 ssl;
    ssl_certificate     /etc/nginx/tgproxy.crt;
    ssl_certificate_key /etc/nginx/tgproxy.key;
    client_max_body_size 20m;
    location /k3y/ {                       # «k3y» — ваш секретный путь
        proxy_pass https://api.telegram.org/;
        proxy_set_header Host api.telegram.org;
        proxy_ssl_server_name on;
        proxy_read_timeout 60s;
    }
    location / { return 404; }
}
```

В поле камеры: `IP_VPS:8443/k3y`. Проверка с любого компьютера: `curl -k https://IP_VPS:8443/k3y/bot<ТОКЕН>/getMe` должен вернуть `"ok":true`. На странице «Состояние» видно, через какой адрес идёт Telegram и последний ответ API.

## Сохранение и загрузка конфигурации

- «Сохранить конфиг» (`/config.json`) скачивает файл `Guard-XXXXXX-config.json` со всеми настройками, включая пароль Wi-Fi и токен бота. Пароль панели попадает в файл, только если он задан вручную.
- «Загрузить конфиг» (`/config`) применяет такой файл и перезапускает камеру. Поля, которых нет в файле, не меняются, поэтому можно держать один общий файл (Wi-Fi, Telegram, прокси) и загружать его на несколько камер.
- Файл проверяется так же, как форма: при ошибке ничего не сохраняется и показывается причина.

## Обновление прошивки через браузер

1. На главной странице панели отметьте «Разрешить обновление прошивки» и сохраните.
2. В Arduino IDE: «Скетч → Экспорт скомпилированного бинарного файла». В папке `build` проекта появится `AIThinkerGuard.ino.bin` — нужен именно он (не `bootloader`, `partitions` или `merged`).
3. Откройте `http://<IP камеры>/update` (или ссылку «Обновить прошивку…» внизу панели), выберите файл, нажмите «Загрузить и перезапустить». Идёт индикатор загрузки; после записи устройство перезапускается само.
4. Нужна схема разделов с OTA (Minimal SPIFFS). Образ проверяется перед переключением: при обрыве или неверном файле остаётся прежняя прошивка.

Доступ к `/update` — тот же логин `admin` и пароль панели. Если панель открыта в интернет (например, через KeenDNS роутера Keenetic), задайте длинный пароль: любой, кто его знает, может залить свою прошивку. Дополнительно можно включить на роутере авторизацию для этого доменного имени.

## Если пароль потерян

Откройте Serial Monitor (115200 бод) и введите команду (конец строки — любой):

| Команда | Действие |
|---|---|
| `password` | показать пароль точки доступа, пароль панели и адрес веб-панели |
| `resetpassword` | вернуть пароль по умолчанию (`Guard` + 5 цифр из MAC) |
| `setpassword <пароль>` | задать свой пароль (8–63 символов) |
| `status` | состояние модулей |
| `reboot` | перезапуск (снимает блокировки модулей) |
| `factoryreset yes` | стереть все настройки; при старте будет создан и напечатан новый пароль |
| `config` | текущие настройки |
| `help` | список команд |
| `about` | описание устройства, назначение и краткая инструкция |

Команды доступны только через USB/UART, то есть при физическом доступе к плате.

## Параметры

| Поле | Значение |
|---|---|
| `N` | Число фото на одно подтверждённое движение, 1–5 |
| `M` | Число фото в ответ на `/getcapture`, 1–5 |
| ID чатов | До 5 числовых ID через запятую; группы — с минусом |
| `X` | Период планового кадра в минутах, 1–1440 |
| `TO` | Минимальный интервал между событиями движения в секундах, 1–86400 |
| IP телефона капитана | Необязательный IP телефона в той же Wi-Fi сети |
| Капитан ушёл через | Минут молчания телефона до «Сторож бдит», 1–60, по умолчанию 10 |
| Тихие часы | Начало/конец `ЧЧ:ММ`, смещение часового пояса в минутах |
| Пароль точки доступа | Не меняется: `Guard` + 5 цифр из MAC |
| Пароль веб-панели и OTA | 8–63 символа; по умолчанию как у точки доступа |
| OTA | По умолчанию выключена; при включении использует пароль веб-панели |

## Структура кода

- `AIThinkerGuard.ino` — запуск и оркестрация режимов.
- `CameraService.*` — камера, кадры движения и JPEG-снимки.
- `TelegramService.*` — отправка сообщений/фото в несколько чатов, команды и inline-кнопки.
- `MotionDetector.*` — сравнение монохромных кадров.
- `WifiPresence.*` — присутствие капитана: ARP-запросы на IP его телефона.
- `ScheduleManager.*` — NTP, часовой пояс и тихие часы.
- `WebConfigServer.*` — защищённая Basic Auth страница конфигурации.
- `Config.*` — структура настроек и их сохранение в NVS.
- `SystemHealth.*` — причина перезапуска, этапы запуска в RTC-памяти, блокировка сбойных модулей, безопасный режим.

## История версий

- **1.8.0** — несколько чатов, команды `/status`, `/help`, `/start` с описанием и inline-кнопками.
- **1.7.0** — меню панели, сохранение/загрузка конфига в JSON, постоянный пароль точки доступа.
- **1.6.0** — Bluetooth удалён; присутствие капитана по Wi-Fi (ARP на IP телефона). Прошивка уменьшилась примерно на 730 КБ.
- **1.5.1** — камера без переинициализации: исправлен сбой снимков при включённом BLE.
- **1.5.0** — настраиваемый адрес API Telegram (свой прокси на VPS при блокировке).
- **1.4.0** — обновление прошивки через браузер: страница `/update` с индикатором загрузки.
- **1.3.1** — captive portal для смартфонов: проверки связи перенаправляются на панель, клиентам защищённой точки доступа не нужен Basic Auth.
- **1.3.0** — простой пароль по умолчанию из MAC, печать настроек при загрузке, команды `config`, `resetpassword`, `about`.
- **1.2.0** — исправлен abort при старте BLE (Wi-Fi без modem sleep), фото отправляются через переинициализацию камеры в JPEG, исправлены таймауты TLS, фоновое переподключение Wi-Fi с точкой настройки, блокировка сбойных модулей и безопасный режим, страница состояния, watchdog.
- **1.1.0** — общий пароль устройства, OTA opt-in, случайная начальная защита, валидация полей, безопасный запуск при пустых токене/MAC или отсутствии камеры, диагностические этапы старта.
- **1.0.0** — первая версия: базовая архитектура классов, настройка AP/Web, Telegram, детектор движения, плановые снимки, расписание, BLE и парольная OTA.
